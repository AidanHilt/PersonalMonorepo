# sync-cog-packages

Discovers releasable container packages under a Nix images directory and
syncs their `[packages.*]` entries into the generated section of
`cog.toml`.

## The standard

A directory under `<images-dir>/` is a releasable package if it contains a
`values.nix` with a top-level, literal-string `tag` **or** `versionPackage`
field — never both.

**Category A** — versioned by cocogitto:
```nix
{
  tag = "0.1.4";
}
```
Syncs into `cog.toml`'s generated `[packages.*]` section. Version comes
from conventional-commit-driven semver bumps.

**Category B** — tracks a nixpkgs attribute, independent of cocogitto:
```nix
{
  versionPackage = "nodePackages.foo";
}
```
Never written to `cog.toml`. Rebuilt whenever its directory (or
`flake.lock`/`flake.nix`) changes; version resolution against
`versionPackage` is a separate mechanism, not part of this tool.

Other cases:
- No `values.nix` → not a package, silently skipped.
- `values.nix` with neither field → not a package yet, silently skipped
  (useful for WIP directories).
- `values.nix` with **both** `tag` and `versionPackage` → **hard error**.
- Either field present but **not** a bare string literal (e.g. computed,
  or using `${...}` interpolation) → **hard error, nonzero exit**. Both
  fields must be literals so tooling (cog's bump hook for `tag`; CI
  matrix construction for either) can read/rewrite them with simple text
  tools rather than a real Nix evaluator.

## Listing packages for CI matrices

`-list=internalVersioned` / `-list=externalPkgVersioned` print the discovered packages of
that category as JSON (one line, array of objects), for direct
consumption via `fromJson(...)` in a GitHub Actions matrix:

```sh
sync-cog-packages -list=externalPkgVersioned
# [{"name":"foo","dir":"...","valuesNixPath":"...","tagPrefix":"foo-","versionPackage":"nodePackages.foo"}]
```

## cog.toml: fixed vs. generated

`cog.toml` is split at a marker line:

```
# ==== GENERATED BY sync-cog-packages: DO NOT HAND-EDIT BELOW THIS LINE ====
```

Everything **above** the marker is opaque, hand-owned text — global
cocogitto config, commit type definitions, bump profiles, etc. This tool
never reads or modifies it beyond leaving it byte-for-byte as-is.

Everything **below** the marker is `[packages.*]` tables, fully
recomputed on every run from the discovered directories:

- Added: a new directory meeting the standard.
- Removed: a directory that no longer exists or no longer has a literal
  `tag`.
- `path`, `changelog_path`, `tag_prefix`, and `bump_hooks` are always
  overwritten — these are fully derived from the directory name and
  path, so there's nothing to preserve.
- Any **other** key you hand-add to a `[packages.<name>]` table (e.g. a
  package-specific override) is preserved across regeneration, as long
  as the package still exists. Supported value types: strings, bools,
  numbers, and arrays of those. Nested inline tables aren't supported —
  if you need one, open an issue against this tool rather than hand
  editing around it.

The first run requires the marker to already be present in `cog.toml`
(add it once, by hand, at the point where the generated section should
start).

## Per-package bump hooks

Per your monorepo having other package types with different release
behavior, this tool does **not** write a global `pre_bump_hooks` /
`post_bump_hooks` entry in the fixed section. Instead, every package
gets its own `bump_hooks` array in its generated table:

```toml
bump_hooks = ["sed -i 's/tag = \".*\";/tag = \"{{version}}\";/' <path>/values.nix"]
```

**Note:** double check the `bump_hooks` key name against the cocogitto
version you're pinning to before relying on this in CI — cocogitto's
per-package hook config key has moved around across versions, and this
was written from best recollection rather than a version-pinned docs
check. `cog bump --help` / the cocogitto config schema for your version
is the source of truth.

## Usage

```sh
sync-cog-packages [flags]

Flags:
  -root string
        repo root (default ".")
  -images-dir string
        images directory, relative to root (default "nix/scripts/images")
  -cog-toml string
        path to cog.toml, relative to root (default "cog.toml")
  -check
        report whether changes are needed without writing; exit 1 if so
```

- Plain run: rewrites `cog.toml`'s generated section in place, prints a
  summary of packages written.
- `-check`: makes no changes; prints an added/removed/changed summary and
  exits 1 if `cog.toml` is stale. Intended for a PR-check workflow.
- Idempotent: running twice in a row with no filesystem changes produces
  no diff and prints "already up to date".

## Suggested CI wiring

- **prepare-release workflow**: run plain (no `-check`) as the first step,
  before `cog bump`, so cocogitto sees the current package set.
- **PR check workflow**: run with `-check` on `pull_request`, fail the PR
  if a new/removed image directory wasn't reflected in `cog.toml`.
- **local pre-commit hook** (optional convenience, not authoritative):
  run plain, scoped to changes under the images directory.

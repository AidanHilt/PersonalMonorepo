# kubernetes/operators

A flake that builds Kubernetes operators from `operators/<name>/` with
zero per-operator Nix code. See [IMPLEMENTERS.md](IMPLEMENTERS.md) for how
the build works and how to modify it; this README is about using it.

## What this flake does

Every directory under `operators/` containing a `go.mod` is discovered as
an operator (the directory name is the operator name). For each one, the
flake builds:

| Package | What it is |
| --- | --- |
| `<name>-binary` | The Go controller binary (`buildGoModule`, `subPackages = [ "cmd" ]`). |
| `<name>-crds` | CRD manifests generated by `controller-gen` from `api/...`. |
| `<name>-rbac` | A `ClusterRole` generated by `controller-gen` from `internal/controller/...` markers. |
| `<name>-image` | A container image (via `nix2container`) running the binary as entrypoint. |
| `<name>-chart` | A fully assembled, `helm package`-d Helm chart (CRDs + generated RBAC/manager manifests + any operator-specific templates). |
| `default` | A `linkFarm` of every operator's `-image` and `-chart`, for building everything at once. |

Adding a new operator never requires touching `flake.nix` or
`nix/mk-operator.nix` — see "Adding a new operator" below.

## Directory contract

An operator directory (`operators/<name>/`) must contain:

- `go.mod`, `go.sum` — its own Go module (not a subpackage of a shared
  module).
- `vendor-hash.nix` — a file containing a single bare Nix string, the
  `vendorHash` for `buildGoModule`. See "Build readiness" below.
- `cmd/main.go` — the binary entrypoint; `buildGoModule` only builds
  `./cmd`.
- `api/v1alpha1/*_types.go` — CRD Go types, annotated with kubebuilder
  markers (`+kubebuilder:object:root`, etc.) for `controller-gen`.
- `internal/controller/*_controller.go` — reconciler(s), annotated with
  `+kubebuilder:rbac:...` markers for every resource/verb they touch. A
  reconciler that touches a resource without a matching marker produces a
  silently incomplete generated `ClusterRole` — see
  [IMPLEMENTERS.md](IMPLEMENTERS.md#gotchas).

Optionally:

- `VERSION` — a file whose contents become the chart's `version`/
  `appVersion`. If absent, the flake's own `shortRev` (or `dirtyShortRev`
  for an uncommitted tree) is used instead.
- `chart/values.yaml` — extra, hand-authored Helm values merged with the
  Nix-generated ones. Must not declare `image.digest` or `chart.version`
  — those keys are owned by the Nix side.
- `chart/templates/*` — extra Helm templates (e.g. a sidecar Deployment)
  copied alongside the generated manager/RBAC templates.

`operators/miura/` is the one operator currently present, and exercises
the full contract including the optional `chart/` override (see
[IMPLEMENTERS.md](IMPLEMENTERS.md) for what it adds).

## Adding a new operator

Add `operators/<name>/` following the directory contract above. Nothing
in `flake.nix` or `nix/mk-operator.nix` needs to change — the new
operator's packages appear automatically next time the flake is
evaluated.

## Building

From this directory (or pass a `#<attr>` path from elsewhere in the
repo):

```
nix build .#<name>-binary   # just the Go binary
nix build .#<name>-crds     # just the generated CRDs
nix build .#<name>-rbac     # just the generated RBAC role
nix build .#<name>-image    # the container image
nix build .#<name>-chart    # the packaged Helm chart
nix build                   # every operator's image + chart
```

## Build readiness

`operators/miura/` does not build out of the box in a network-restricted
environment:

1. `go.sum` is currently empty. Run `go mod tidy` inside
   `operators/miura/` with network access to populate it.
2. `vendor-hash.nix` currently holds a placeholder
   `sha256-AAAA...` string. Run `nix build .#miura-image` once — it will
   fail with the real hash in the fixed-output-derivation mismatch
   message — and paste that hash back into `vendor-hash.nix`.

Once both are real, `nix build .#miura-image` / `.#miura-chart` should
succeed with no further changes.

## Local dev loop

[`reconcile-operator`](../../nix/scripts/scripts/reconcile-operator)
(from `nix/scripts`) watches `operators/<name>`, `nix/`, `flake.nix` and
`flake.lock`, and on any change rebuilds `<name>-image`/`<name>-chart`,
loads the image into Docker and a local `kind` cluster, and
`helm upgrade --install`s it into a `<name>-dev` namespace (or
`--namespace <ns>`), restarting the manager Deployment so it picks up the
freshly loaded image. It uninstalls the release when you stop it. See
that script's `--help` for the full flag list, and
[IMPLEMENTERS.md](IMPLEMENTERS.md#gotchas) for a caveat about how it
tags/pulls the image relative to what the chart's manager template
actually references.

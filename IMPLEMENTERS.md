# Implementers

This file is for people (and agents) who are modifying or reading the
source of this repository, as opposed to just using one of its projects.

## Philosophy

HomeOps is the idea that a homelab deserves the same rigor as a production cloud environment. If something matters, it is defined in code, reviewed like code, and reproducible from this repository.

- **Declarative first.** Hosts, clusters, applications, secrets wiring and container images are described, not hand-configured.
- **Nix as the glue.** Nix is the primary build tool, including in unusual places such as generating Terraform and building container images.
- **Git is the source of truth.** Cluster state is reconciled from this repository (GitOps) rather than changed by hand.
- **Projects stand on their own.** Each top-level project is a first-class project. Many are generic enough to be lifted out and adapted for your own setup.
- **Reproducible and reviewable.** Changes go through version control, automated checks and conventional commits.

## Convention

- `README.md` files describe how to *use* a project: what it is, how to
  consume it, how to adapt it.
- `IMPLEMENTERS.md` files describe how to *modify or read* a project:
  architecture, directory layout, how things fit together, gotchas.
- The root `AGENTS.md` only states this convention and points here; it is
  not a place for implementation detail.

Before modifying code anywhere in this repository, read this file and the
nearest component `IMPLEMENTERS.md` to the code you're touching.

## Architecture / flow overview

- `nix/mono-flake` defines hosts (NixOS, nix-darwin, home-manager) that
  provision the Kubernetes cluster(s).
- `terragrunt/` runs the Terraform modules generated by `nix/terraform`
  (via terranix) to configure cluster-adjacent infrastructure such as
  Vault, Vault PKI, Authentik and SeaweedFS.
- ArgoCD (configured under `kubernetes/argocd`) syncs the Helm charts in
  `kubernetes/helm-charts` into the cluster via a `master-stack` chart
  (`kubernetes/helm-charts/k8s-resources/master-stack`), with per-cluster
  values supplied from `kubernetes/argocd/configuration-data/<cluster>/`.

## Repo-wide tooling

- **cocogitto** (`cog.toml`) drives conventional-commit-based versioning
  and changelogs. The generated section of `cog.toml` (below the
  `GENERATED BY sync-cog-packages` marker) is maintained automatically by
  the `sync-cog-packages` script (`nix/scripts`) rather than hand-edited.
- **renovate** (`renovate.json`) — dependency update automation; the repo
  config currently only sets `prHourlyLimit: 10`, relying on Renovate's
  defaults otherwise.
- **pre-commit** (`.pre-commit-config.yaml`) hooks:
  - `detect-secrets` — scans for secrets against `.secrets.baseline`.
  - `trailing-whitespace` — strips trailing whitespace (excludes `*.age`).
  - `check-executables-have-shebangs`, `check-json`, `detect-private-key`,
    `no-commit-to-branch` — standard pre-commit-hooks checks.
  - `check-jsonschema` — validates `.atils_jobconfig.json` against
    schemas in `json-schemas/`.
  - `sync-cog-packages` (local) — keeps `cog.toml`'s generated section in
    sync with `nix/custom-images/images/`.
  - `sync-pi-extensions` (local) — keeps
    `nix/agentic-ai-stack/extensions/package-lock.json` and
    `git-extensions.nix` in sync via
    `nix/agentic-ai-stack#update-pi-extensions`.
- **GitHub workflows** (`.github/workflows/`):
  - `check-cog-sync.yml` — on PRs touching `nix/custom-images/images/**`,
    checks that `cog.toml` is in sync with the image directories.
  - `helm-charts-on-merge.yml` — builds and pushes changed Helm charts to
    an OCI registry; currently `workflow_dispatch`-only (manually
    triggered; marked TODO/not-ready-to-delete in the workflow itself).
  - `prepare-container-release.yml` — on pushes touching
    `nix/custom-images/images/**` or its flake files, syncs `cog.toml`
    and runs `cog bump` (scoped per-package normally, or force-bumping
    every self-versioned package when the images flake's lock/nix files
    changed) to prepare container image releases.
  - `release-container-pr-merged.yml` — once a `release/auto` PR from
    `prepare-container-release.yml` merges (PR release mode only), pushes
    the computed tags so tag-triggered release workflows can fire.
  - `release-internal-versioned-image.yml` — on `<package>-v<semver>`
    tags, builds and pushes per-arch images for cocogitto-managed
    ("self-versioned") packages and assembles/publishes a multi-arch
    index plus a GitHub Release.
  - `release-pkg-versioned-images.yml` — on pushes touching
    `nix/custom-images/images/**` or its flake files, builds, tags and
    releases packages whose version tracks an upstream nixpkgs package
    ("package-versioned") rather than being cocogitto-managed.

## Naming note

"atils" is a legacy project name that predates the current repository
layout. It's still reused in places (image names such as `atils-avp`,
config file names such as `.atils_jobconfig.json`) — keep using it where
it already exists rather than renaming on sight.
